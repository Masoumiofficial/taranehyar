## ساختار مخزن

```
taranehyar/            سورس افزونه وردپرس (نصب‌شونده)
├── taranehyar.php     فایل اصلی افزونه
├── includes/          کلاس‌های تنظیمات، صفحات ادمین و پردازش فرم‌ها
├── assets/            CSS / JS / فونت
├── hostdl/            اسکریپت‌های هاست دانلود (جداگانه روی هاست دانلود نصب می‌شود)
│   ├── config.php     توکن امنیتی
│   ├── bootstrap.php  توابع مشترک (احراز هویت، دانلود امن، تگ ID3)
│   ├── curl-*.php     endpointها
│   ├── getid3/        کتابخانه تگ‌گذاری ID3 (GPL)
│   └── PROTOCOL.md    قرارداد ارتباطی افزونه ↔ هاست دانلود
├── readme.txt         صفحه محصول (وردپرس)
└── uninstall.php
build.sh               ساخت بسته‌های انتشار در dist/
publish-release.sh     انتشار ریلیز گیت‌هاب
.github/workflows/     وورکفلوهای GitHub Actions (CI + Release)
ANALYSIS.md            گزارش تحلیل و آماده‌سازی برای فروش
```

## وورکفلوها (GitHub Actions)

| وورکفلو | فایل | اجرا با | کار |
|---|---|---|---|
| **CI** | `.github/workflows/ci.yml` | push روی `main` و شاخه‌های `arena/**`، هر PR، اجرای دستی | بررسی نحو همه فایل‌های PHP (`php -l`)، اجرای تست‌های HostDL/آرشیو/تنظیمات/صف روی PHP 7.4/8.1/8.3، ساخت بسته‌ها با `build.sh` و بارگذاری آن‌ها به‌عنوان Artifact |
| **Release** | `.github/workflows/release.yml` | push برچسب `v*`، اجرای دستی | اجرای تست‌ها، ساخت GitHub Release با ZIPهای نام‌عمومی و نسخه‌دار و در صورت وجود PDF راهنمای همان نسخه، سپس بررسی پیوست‌ها |

اجرای دستی وورکفلو Release (از تب **Actions ← Release ← Run workflow** یا با `gh`):

```bash
# فقط بررسی و ساخت بسته‌ها، بدون انتشار (پیشنهاد می‌شود اول این را بزنید)
gh workflow run release.yml -f mode=dry-run

# انتشار واقعی همین نسخه (نسخه از هدر افزونه خوانده می‌شود)
gh workflow run release.yml -f mode=publish

# به‌روزرسانی ریلیز موجود (مثلاً پیوست دوباره فایل‌ها به v1.0.0)
gh workflow run release.yml -f mode=publish -f target=v1.0.0

# انتشار پیش‌نویس
gh workflow run release.yml -f mode=publish -f draft=true
```

> برای انتشار نسخهٔ بعدی: هدر `Version:` افزونه، `Stable tag:` در `readme.txt` و بخش `## <نسخه>` در `CHANGELOG.md` باید یکسان باشند؛ سپس برچسب را روی commit انتشار بسازید و push کنید. آخرین انتشار عمومی این مخزن `v2.0.0` است.

## ساخت بسته انتشار

```bash
./build.sh
```

خروجی:
- `dist/taranehyar.zip` — افزونه (نصب از پیشخوان وردپرس)
- `dist/taranehyar-hostdl.zip` — فقط اسکریپت‌های هاست دانلود

## پیکربندی سریع

1. افزونه را نصب و فعال کنید.
2. بار اول محتوای `hostdl/` را روی هاست دانلود آپلود کنید و در `config.php` یک توکن تصادفی طولانی بگذارید؛ هنگام به‌روزرسانی HostDL فایل `config.php` فعلی را حفظ کنید.
3. در «پنل موزیک ← تنظیمات»: آدرس هاست دانلود، آدرس endpointها (`curl-music.php` برای تک آهنگ/ریمیکس/نوحه)، همان توکن، اطلاعات سایت و شناسه دسته‌بندی‌ها را وارد کنید.
4. در بخش «سازگاری با قالب»، در صورت نیاز کلیدهای متا و تکسونومی خواننده (پیش‌فرض `singer`) را مطابق قالب خود تنظیم کنید. کلیدهای متای ترانه‌سرا، آهنگساز، تنظیم‌کننده، میکس/مسترینگ و تهیه‌کننده نیز قابل نگاشت‌اند؛ فیلد هر عامل را جداگانه در همان بخش روشن یا خاموش کنید. برای آلبوم، `album` تعداد ترک‌هاست (عدد)؛ اطلاعات هر ترک با اندیس یک‌مبنا در کلیدهای `album_1_...` تا `album_15_...` ذخیره می‌شود و آرایهٔ قدیمی همچنان در `album_dl` باقی می‌ماند.
5. در تنظیمات، عنوان‌ها و سه قالب فارسی/انگلیسی هر نوع محتوا را یک‌بار تنظیم کنید. فرم ارسال فقط قالب را از فهرستی که متن کامل گزینه‌ها را نشان می‌دهد انتخاب می‌کند؛ نام خواننده و اثر خودکار جایگزین می‌شوند و نیازی به ویرایش متن برای هر پست نیست. فیلدهای عوامل فعال در فرم تک‌آهنگ، ریمیکس، نوحه و موزیک‌ویدیو ظاهر می‌شوند و در متای قابل‌نگاشت ذخیره می‌شوند؛ ردیف‌های آن‌ها در کارت مشخصات هم تابع تنظیم «نمایش مشخصات اثر و عوامل» است. متن معرفی، «دربارهٔ اثر» و مشخصات ساختاریافته در کارت‌های مجزا نمایش داده می‌شوند؛ کیفیت در کارت مشخصات می‌آید و عوامل تولید در متن آزاد دوباره تکرار نمی‌شوند. متن ترانه در فیلد جداگانه و متای `music_txt` ذخیره می‌شود و برای جلوگیری از تکرار به متن اصلی پست اضافه نمی‌شود. افزونه به پست‌های جدید برچسب WordPress اضافه نمی‌کند؛ دسته‌های انتخاب‌شده و پیوندهای داخلی به اثر و آرشیو خواننده استفاده می‌شوند. برای کنترل انتقال‌ها به منوی مستقل «وضعیت انتقال‌ها» بروید و از اجرای فوری، تلاش مجدد، لغو صف و پاک‌سازی تاریخچه استفاده کنید. تنظیمات SEO بر پست‌های جدید اعمال می‌شوند و تنظیمات سراسری Yoast، Rank Math یا SEOPress را تغییر نمی‌دهند.

ظاهر افزونه به‌صورت پیش‌فرض روشن است و از دکمهٔ بالای صفحه می‌توان آن را به تیره تغییر داد.

تک‌آهنگ، ریمیکس و نوحه در ریشه‌های جداگانهٔ `music/a/alireza-rozegar/`، `remix/a/alireza-rozegar/` و `nohe/a/alireza-rozegar/` ذخیره می‌شوند؛ برای فعال‌شدن ریشه‌های جدید، `bootstrap.php` و `curl-music.php` هاست دانلود را به‌روزرسانی کنید و `config.php`/توکن را حفظ کنید. ویدیو، آلبوم و لیچ نیز ریشه‌های مستقل دارند. جزئیات مسیرهای جدید و سازگاری با مسیرهای قدیمی در [`taranehyar/hostdl/PROTOCOL.md`](taranehyar/hostdl/PROTOCOL.md) آمده است.
